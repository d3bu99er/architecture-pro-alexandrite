# Выбор и настройка мониторинга в системе

## Требования

| **№** | **Участники / системы** | **Сценарий**        | **Описание**                                                                                                                                        |
|:-----:|:------------------------|:--------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------|
|   0   | Все системы            | Все сценарии        | Для каждого требования необходимо построить метрики и визуализацию. При отклонении значений — отправка уведомления в выделенный Telegram-канал. |
|   1   | Shop API, CRM API, MES API | API-запросы     | Требуется отслеживать количество ответов с кодом 500 для контроля роста ошибок.                                                                     |
|   2   | Shop API, CRM API, MES API | API-запросы     | Необходимо контролировать время ответа API и реагировать на его увеличение.                                                                        |
|   3   | Shop API, CRM API, MES API | API-запросы     | Требуется анализировать нагрузку (RPS) по сервисам и endpoint’ам для своевременного выявления роста трафика.                                       |
|   4   | Shop API, CRM API, MES API | API-запросы     | Необходимо контролировать использование ресурсов (CPU и RAM) подами.                                                                               |
|   5   | RabbitMQ, CRM API, MES API | Очереди сообщений | Требуется отслеживать время обработки сообщений из RabbitMQ.                                                                                        |
|   6   | RabbitMQ, CRM API, MES API | Очереди сообщений | Необходимо контролировать количество сообщений в очередях RabbitMQ.                                                                                |
|   7   | Shop DB, MES DB        | Работа с БД         | Требуется отслеживать объём используемой памяти БД для предотвращения отказов.                                                                      |
|   8   | Shop DB, MES DB        | Работа с БД         | Необходимо контролировать количество запросов и подключений к БД.                                                                                   |
|   9   | Shop DB, MES DB        | Работа с БД         | Требуется выявлять медленные запросы для последующей оптимизации.                                                                                   |
|  10   | Shop DB, MES DB        | Работа с БД         | Необходимо контролировать загрузку CPU и RAM базы данных.                                                                                            |
|  11   | S3                     | Работа с файлами    | Требуется отслеживать занимаемое хранилищем пространство.                                                                                            |

## Решение

### Мониторинг API

Для API целесообразно использовать подход «четырёх золотых сигналов». Каждая метрика содержит label Service для идентификации источника.

| **Метрика**              | **Ярлыки**                                 | Покрываемые требования |
|:-------------------------|:-------------------------------------------|------------------------|
| Количество запросов (RPS) | Service, Method, Endpoint, Status          | 1, 3                   |
| Время ответа             | Service, Percentile, Method, Endpoint      | 2                      |
| Загрузка CPU             | Service                                    | 4                      |
| Использование памяти     | Service                                    | 4                      |

### Мониторинг RabbitMQ

Для очередей применяется подход USE (Utilization, Saturation, Errors).

| **Метрика**                              | **Ярлыки**     | Покрываемые требования |
|:-----------------------------------------|:---------------|------------------------|
| Время обработки сообщений                | Service, Queue | 5                      |
| Сообщения в DLQ                          | Queue          | 6                      |
| Размер очередей                          | Queue          | 6                      |

### Мониторинг базы данных

Для БД используется адаптированный набор метрик, аналогичный «золотым сигналам».

| **Метрика**           | **Ярлыки**                  | Покрываемые требования |
|:----------------------|:----------------------------|------------------------|
| Размер базы           | Instance                    | 7                      |
| Количество запросов   | Instance, Query             | 8                      |
| Количество соединений | Instance                    | 8                      |
| Время выполнения      | Instance, Query, Percentile | 9                      |
| Блокировки            | Instance                    | 9                      |
| CPU                   | Instance                    | 10                     |
| Память                | Instance                    | 10                     |

### Мониторинг S3

Контролируется объём используемого пространства.

| **Метрика**        | **Ярлыки** | Покрываемые требования |
|:-------------------|:-----------|------------------------|
| Размер хранилища   |            | 11                     |

## Обоснование

Внедрение мониторинга и алертинга необходимо для обеспечения управляемости системы.

Это позволит:
- выявлять и устранять инциденты до появления пользовательских жалоб;
- обнаруживать деградацию производительности на ранних этапах;
- фиксировать инциденты вне рабочего времени;
- своевременно реагировать на атаки и аномалии;
- предотвращать отказ сервисов из-за нехватки ресурсов;
- выявлять редкие и трудно воспроизводимые ошибки;
- отслеживать технические причины задержек заказов.

## План внедрения

- Реализовать endpoint `/metrics` для всех API (Shop, CRM, MES);
- Установить экспортёры метрик для БД (например, pgwatch, pgmetrics);
- Подключить экспортёр для S3;
- Развернуть экспортёр для RabbitMQ;
- Настроить Prometheus для сбора метрик;
- Развернуть Grafana и подключить к Prometheus;
- Настроить дашборды для всех ключевых метрик;
- Настроить Alertmanager для обработки алертов.
